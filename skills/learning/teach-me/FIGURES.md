# Figures

Every figure is an inline SVG generated by a `figsN.py` that imports [figlib.py](figlib.py). Geometry is computed, never hand-typed: a tree is laid out from the algorithm's own split rule, so the picture cannot disagree with the code.

## The storyboard

One figure of the **whole machine** first (who holds what, what crosses the network, what is compared), then one figure per **state change or sequence**: each case of the argument, each level of a hand trace, each act of the run. A figure that would need more than one caption sentence is two figures. Fifteen figures for a forty-minute lesson is normal.

Each figure carries an `aria-label` that describes the picture in one sentence and a `figcaption` that tells the reader what to see in it and why it matters ("The hard case, 3 → 5. Look for root3 inside the new tree. It is not there.").

## Conventions

- `viewBox="0 0 760 H"`; shapes in `<g class="ink sketch">`, text in `<g class="lbl">`. `figures.js` supplies the arrowheads `#arr`, `#arr-acc`, `#arr-ok`, `#arr-bad` and the `#sketch` wobble filter; load it once per page.
- Palette (from `figures.css`): strokes `acc` (burnt sienna), `ok` (green), `bad` (red), `dash`, `thin`, `thick`; fills `paper`, `soft`, `tint`, `oktint`, `badtint`; text `sm`, `big`, `hand` (italic serif, for captions inside the picture), `t-acc`, `t-ok`, `t-bad`, `t-muted`, `mid`, `end`.
- Meaning is carried by the same classes in every figure: **dashed + accent** = given in the proof, **green tint** = computed by the verifier, **accent tint** = the node the argument is about, **red tint** = tampered, `hand` text = the sentence the figure is making.
- Node boxes are 54 × 20 with the label inside; leaf names sit 14 px below the leaves; a hash value sits to the side of its box (`end`-anchored on the left or start-anchored on the right), never beneath a node whose edges go down.
- Storyboards are rows of equal panels with arrows between; ladders are two columns of rungs with the shared inputs in a middle column feeding one or both sides; timelines are cards joined by labelled arrows with the state box beneath.

## Text width rule of thumb

Monospace 12 px ≈ 7.2 px per character; `sm` 10.5 px ≈ 6.3 px; `hand` 13.5 px italic ≈ 6.5 px. Check every label against the box or gap it sits in before rendering; a 16-character `sm` label needs 100 px.

## Render and look

```python
figlib.harness(FIGS, out_dir="shots", css_url="file:///abs/path/to/assets/", per_page=3)
figlib.render("shots/figs_1.html", "shots/figs_1.png")     # headless Chrome, 900 × 1500
```

Then open every PNG and read it as the learner will. Fix, regenerate, re-render. The collision checklist, in the order they usually appear:

1. A label wider than its box or panel (right edge past the box).
2. A side label crossing a tree edge that runs beside the node.
3. A left-column label overlapping the leftmost node of a tree that starts too far left.
4. A bottom caption crossing a divider line that runs to the bottom of the viewBox.
5. An arrow label wider than the gap between the boxes it joins.
6. Two labels stacked less than 14 px apart.
7. Anything past x = 760 or below the viewBox height.

Done means you looked at the final render of every figure, not that the script ran.

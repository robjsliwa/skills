Set up the project

1 Create the app beside PhoneCore

In Xcode choose File › New › Project, then iOS › App. Name it SecondLine, choose your team, SwiftUI, Swift, and Swift Testing with XCTest UI Tests. Save it in the folder that holds PhoneCore/, and leave "Create Git repository" off: that folder already is one.

Product › Build (⌘B)

The template's "Hello, world!" app builds with no errors.

Get a working project before changing anything, so any error after this is yours to find in one step, not a mix of setup and code.

2 Use PhoneCore as a local package, in Swift 6 mode

File › Add Package Dependencies…, then Add Local…, select the PhoneCore folder, and tick the SecondLine target. Then in the target's Build Settings set Swift Language Version to Swift 6, and do the same for SecondLineTests.

⌘B again

It still builds, and PhoneCore is listed under General › Frameworks, Libraries, and Embedded Content.

This is Go's replace … => ../PhoneCore: the app points at the package by path. Swift 6 mode makes the compiler check thread safety now, while the only thread is the one you tap on, instead of in Lesson 4 when Twilio's callbacks arrive.

what Xcode 26's new-project template sets for you

New app targets default to MainActor isolation, so every type in the app is main-actor isolated unless it says otherwise. Packages do not get that default, which is why PhoneCore's types had to be Sendable in Lesson 1. You will meet the consequence in step 5, the tests.

why do/catch instead of Result { … }

The shorter form does not compile: the closure's error type is inferred as any Error, not ParseError. A do block whose only throwing call throws ParseError does infer it.

why the suite needs @MainActor

Phone is main-actor isolated because of the app target's default (step 1's template). The test target has no such default, so without the annotation Swift 6 rejects let phone = Phone() with {{value:mainactor_error}}.

On your iPhone

6 Run it on the phone in your pocket

Connect the iPhone, tap Trust, turn on Settings › Privacy & Security › Developer Mode, choose your team under Signing & Capabilities, pick the phone as the run destination.

⌘R

SecondLine opens on the phone. Type your own number: Call lights at the tenth digit. Tap it, then Ring and Answer in the Simulated network box, then hang up: the dial pad returns with your number still there.

Nothing cleared typed during the call, so redial comes for free: a consequence of storing causes, not something anyone wrote.

When it doesn't work

No such module 'PhoneCore'
The package is added but not linked to the target. Add it under General › Frameworks, Libraries, and Embedded Content.
main actor-isolated default value in a nonisolated context
The test suite is missing @MainActor (step 5's Under the hood box says why).

Challenges

The key-ten trap

Type 14155552671, the way people often say it. Predict when Call first turns green and for which number, then try it. Why is that number impossible?

You're done when you can say which rule in Lesson 1's parser allowed it.

Hint

Look at what the parser does with ten digits that have no +.

Plus the phone way

Remove the + key and make a long press on 0 produce +. Decide whether that rule belongs in KeyButton, DialerView, or Phone, and write the test that pins it.

You're done when the test fails before your change and passes after.
